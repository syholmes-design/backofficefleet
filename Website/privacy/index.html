Privacy Policy

This page is a launch draft for owner and legal review. It describes the current public website experience and should be finalized before production legal reliance.

Status

No production submission wiring is represented here.

Current public forms validate locally and display a review message unless secure backend submission is later approved.

Last updated: July 29, 2026

Scope

This Privacy Policy applies to the BackOfficeFleet public website and public demo pages. Public product pages use illustrative and synthetic data. Do not submit sensitive documents, credentials, private driver records, account numbers, or protected records through public forms.

Information You Choose to Provide

Public contact, demo, Priority Fleet, assessment-roadmap, government, aggregator, driver, and BOF Vault inquiry forms ask for basic business contact details, organization context, request type, fleet or network context, and a short message. If an approved secure backend endpoint is configured, those forms transmit the request to BOF's server-side intake function and return a public reference after storage. If the backend endpoint is not configured, the forms validate in the browser and explain that online submission is being finalized and the information has not been transmitted.

Assessment Roadmap Requests

If you ask for a detailed readiness roadmap from the public assessment page, the page may attach the preliminary assessment summary entered in that browser session, including audience type, readiness band, section indicators, top gaps, and recommended BOF workflows. BOF does not collect every question answer in the public intake request unless a separate approved workflow is created.

Local Draft Convenience

The public intake script may use browser session storage on the same device to remember basic contact, organization, and fleet context while you move between public intake pages. This is intended to reduce repeated typing in the same browser session. It is not a server-side BOF record and should not be used for sensitive information.

Website Operations

The site loads local scripts, images, styles, and demo data needed to display the pages. The current audit did not identify analytics tags or advertising trackers in the public pages. Some demo or portal experiences may use browser local storage to preserve demonstration state on the same device.

Technical Anti-Abuse Information

If backend intake is enabled, BOF may process limited technical information needed to protect the form, such as source page, allowed-origin checks, referrer or campaign context, form timing, duplicate-submission signals, rate-limit signals, and an anti-abuse request fingerprint. BOF should not use public intake to collect sensitive documents or protected records.

How Information May Be Used

If a future approved submission path is added, information provided through a BOF form may be used to respond to inquiries, prepare demo conversations, review Priority Fleet fit, evaluate readiness-roadmap requests, route government or aggregator inquiries, improve website content, and support ordinary business communication.

Sharing

BackOfficeFleet does not describe any public website sale of personal information in this launch draft. Information may be shared with service providers or advisors only as needed to operate BOF services, respond to requests, protect the business, or comply with applicable obligations.

Retention Proposal

During development and controlled testing, test submissions should be clearly marked and removable by authorized cleanup. Before production launch, BOF should approve retention limits for public-intake records, reviewer notes, notifications, and deletion or export requests. This page should not be treated as evidence of an automated deletion program until such a program is implemented and reviewed.

Security

Public website pages are not a secure document intake channel. Do not use them to submit CDL records, medical-card information, driver qualification files, tax identifiers, payment or financial details, authenticated portal records, production chat content, government protected records, private uploads, or regulated data. BOF Vault and operational workflows should use approved secure environments before any private or regulated data is collected, stored, reviewed, or transmitted.

Questions

Use the Contact page for privacy questions or website inquiries.
