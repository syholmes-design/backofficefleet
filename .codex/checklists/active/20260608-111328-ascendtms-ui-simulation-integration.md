## Goal

Complete a source-informed, static AscendTMS simulation integration pass across the BOF demo so the client can see that AscendTMS is a real TMS/load workflow source and BOF is the readiness, document, exception, audit, release-decision, and simulated handoff layer.

## Operating Decision

The user explicitly reintroduced AscendTMS for this pass because the client complained that the demo did not integrate AscendTMS enough.

This checklist therefore allows visible `AscendTMS` inside the demo/integration workflow where it helps the client understand the partner source system. It does not authorize a live integration.

## Hard Scope Boundary

- Build with static HTML, CSS, vanilla JavaScript, JSON, and static image assets only.
- Do not add real AscendTMS API calls, EDI, webhooks, live sync, credentials, `.env`, auth, backend routes, database writes, uploads, React, Next.js, TypeScript, npm packages, build tooling, or `node_modules`.
- Do not log into an AscendTMS account, scrape private account data, store credentials, or copy private client records unless the user explicitly changes the authorization boundary.
- Use public AscendTMS/help/source material and any user-supplied authorized screenshots only as references for a static simulated UI.
- Do not claim BOF has a working AscendTMS production integration.
- Do not position BOF as replacing AscendTMS.
- Do not position AscendTMS as the source of truth for BOF driver compliance or BOF document readiness.

## Source Findings To Preserve

- AscendTMS is the named real TMS/load workflow source system for this pass.
- AscendTMS should manage load creation, dispatch workflow, load tenders, customer/carrier load details, status, uploaded load documents, and accounting/TMS handoff.
- BOF should manage driver compliance, driver document vault, carrier packet readiness, release readiness, missing-document tracking, pre-trip/in-route/post-trip enforcement, exception ownership, settlement holds, claims packet support, audit trail, and management decision records.
- The client specifically questioned whether Codex had anything real to base the AscendTMS mockup on, so the UI pass must be source-backed rather than generic.
- The current BOF site already has neutral TMS-import scaffolding. This pass should deliberately upgrade the demo to a more recognizable AscendTMS partner simulation, not erase BOF's current proof depth.
