# Accessibility And Clarity Reviewer

Use this skill when readability, usability, or accessibility basics are part of the work.

## Purpose

Make the new BOF website clear and usable.

## When To Use

- Contrast
- Font size
- Button labels
- Form labels
- Keyboard navigation
- Screen reader basics
- Plain-language UX
- Empty states
- Loading states

## Procedure

1. Identify the user's task and likely confusion points.
2. Review labels, contrast, typography, focus, and state language.
3. Replace clever or vague wording with clear wording.
4. Recommend accessibility basics without turning the task into a full compliance audit.
5. Define acceptance criteria.

## Checks

- Are labels clear?
- Is text readable?
- Are contrast and focus states acceptable?
- Can keyboard users understand the flow?
- Do empty/loading/error states explain what is happening?

## Output Format

```markdown
## Accessibility And Clarity Review

Surface:
Clarity issue:
Accessibility basics:
Recommended wording/design:
Acceptance criteria:
```

## Safety Boundaries

- Do not expand into legal compliance unless the user asks.
- Keep recommendations practical for the website/demo shell.
